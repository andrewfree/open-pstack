# Model and provider registry design

Design for [GitHub issue #103](https://github.com/ericlitman/open-pstack/issues/103), prepared on 2026-10-11 against `main` at `c5c8e23` (Open Pstack 1.6.1, Cursor pstack 0.15.17). Cursor has no pstack commits after the recorded sync point `978ca6e`.

**Status: approved by Eric on 2026-10-11.** His answers to the six open questions are recorded under "Decisions" and are folded into the design below. Implementation issues: U1 #155, U2 #156, U3 #157. This document changes no runtime file.

## Decision

- **One source.** The registry is TypeScript in a new `registry/` directory next to the external runner (`plugins/pstack/skills/poteto-mode/scripts/runner/`). Family entries and role defaults are data in `registry/models.ts`. The only provider list is one array in `registry/providers.ts`.
- **Providers are code.** Each provider is one module in `runner/providers/<id>.ts` that implements one adapter contract. `run.ts` keeps every timing, retry, fallback and receipt policy, and loses every provider `switch`.
- **Generated outputs.** `registry/render.ts` writes the model catalog, `plugins/pstack/skills/poteto-mode/references/model-catalog.md`, and every `plugins/pstack/agents/pstack-<family>-<effort>.md` file. A Bun test fails CI when a generated byte differs from the render. `provider-dispatch.md` keeps only hand-written rules and links to the catalog.
- **Narrow live gate for model changes.** The verifier gains a `catalog` feature for the model catalog and the generated agents. After U2, a change that edits only the registry runs the runner, setup and catalog checks, not every skill check.
- **Unregistered models still run.** The runner passes a `(provider, model)` pair that the registry does not list to the CLI unchanged, as it does today.
- **Role pointers.** Cursor-derived files name a role and link to its role default. They name no descriptor and no model. A model or provider change then edits no Cursor-derived file.
- **Cost of the three required entries.**
  - GPT-6.1 Sol: one family entry in `registry/models.ts`.
  - GPT-6 Luna, optional: one family entry in `registry/models.ts`.
  - Devin CLI: one adapter module and its test, one line in `registry/providers.ts`, and one SWE-2 family entry.
- **Unchanged rules.** No implicit runtime timeout. No weaker-model fallback. No retry on another provider. The parent resolves the route once, and children never detect the harness.

These names are new in this document. Each is defined once here:

- **Family entry:** one registry record for one model family. It renders as one model-matrix row. Issue #103 calls it a model entry.
- **Kept predecessor:** an older model ID of a family. It runs unchanged until `/setup-pstack` replaces it. `codex:gpt-5.6-sol` is one today.
- **Released pair:** a `(provider, model)` pair that any revision of the model matrix on `main` contained.
- **Provider sidecar:** a file that the provider CLI writes at a path the runner reserves. Devin's `--export` JSON is one.
- **Model catalog:** the generated file `plugins/pstack/skills/poteto-mode/references/model-catalog.md`. It holds the model matrix, kept predecessors and normalization rules, the route table, provider notes and role defaults. Only `render.ts` writes it.
- **`default` effort:** the effort value that passes no effort to the CLI, so the CLI or model uses its own setting. A family offers it only when its entry lists it.
- **Role pointer:** text in a Cursor-derived file that names a role and links to its role default, instead of naming a descriptor.
- **Role default:** the first-run descriptor list for one model-sheet role, such as `arena runners`.

Paths below are relative to `plugins/pstack/skills/poteto-mode/scripts/runner/` unless they start with `plugins/`, `tests/`, `docs/`, `.claude/` or a repository-root file name.

## Problem

Model and provider facts live in four places today:

- **The model matrix** in `provider-dispatch.md`. The parent model reads it at run time, and `model-matrix.test.ts` parses it.
- **Three `switch` statements and five `run.ts` functions.** `commands.ts` builds argv, `parse-output.ts` parses output, and `run.ts` holds env stripping, preflight classification, failure status and model proof per provider.
- **Setup's probe table and first-run role map** in `setup-pstack/SKILL.md`.
- **Slug copies in twelve Cursor-derived files.** `tests/skill-collision-repro.sh` keeps eleven of them equal. The twelfth, `poteto-mode/SKILL.md:94`, still says "GPT-5.6 Sol max" although the Sol default is `gpt-6.1-sol`, because the bash checks match descriptor syntax and that line is prose.

Adding a provider touches about 12 files. Changing a default model touches about 15. Each edit to a Cursor-derived line conflicts on the next Cursor sync.

Four constraints shape the design:

1. **Two consumers.** The parent model reads markdown at run time and runs no code. `setup-pstack/SKILL.md` forbids "a runtime resolver". The runner and the tests are code.
2. **Static agent files.** Claude Code loads `plugins/pstack/agents/*.md` at plugin install, so those files cannot be produced at run time.
3. **Identity is `(provider, model)`.** Devin serves other vendors' models (`claude-opus-5-5-max`, `gpt-6-luna-high`), and it puts the effort in the model ID (`swe-2-high`).
4. **History.** Sheets from releases before v1.5.0 hold `grok:grok-4.6`, which no current rule covers. Exact Claude pins (#54) collide with the read-time normalization that rewrites `claude-opus-<revision>` to `opus`.

## Usage (caller's view)

### The three required entries

| Change | Edited by hand | Regenerated |
|---|---|---|
| GPT-6.1 Sol | `registry/models.ts` | the model catalog |
| GPT-6 Luna | `registry/models.ts` | the model catalog |
| Devin and SWE-2 | new `providers/devin.ts`, new `providers/devin.test.ts`, one line in `registry/providers.ts`, one entry in `registry/models.ts` | the model catalog |

### How the parent finds a role default and a route

Example: a Claude Code parent runs `/pstack:arena`, and the model sheet has no `arena runners` line.

1. Arena step 3 links to `model-catalog.md#role-defaults`. That section of the model catalog holds the complete first-run sheet, so each line reads like the user's own sheet:

   ```text
   arena runners: claude:opus@max, codex:gpt-6.1-sol@max, grok:grok-4.7@xhigh
   ```

2. The parent applies the catalog's predecessor and normalization rules, then matches `(provider, model)` to one model-matrix row:

   | Family | Label | Provider | Model | Default effort | Selectable efforts | Claude-native agents | Status | Upstream pstack choice |
   |---|---|---|---|---|---|---|---|---|
   | opus | Opus | claude | opus | max | low medium high xhigh max | `pstack-opus-<effort>` | default | opus |
   | sol | GPT-6.1 Sol | codex | gpt-6.1-sol | max | low medium high xhigh max ultra | - | default | gpt-5.6-sol-max |
   | luna | GPT-6 Luna | codex | gpt-6-luna | max | low medium high xhigh max | - | optional | - |

3. The parent reads the provider's row in the catalog's route table:

   | Provider | Claude Code parent | Codex parent | Prompt | Model proof | Child environment | Host prerequisites |
   |---|---|---|---|---|---|---|
   | claude | native `Agent` | external runner | stdin | provider report | inherited; a writer drops `GIT_*` | - |
   | codex | external runner | native `spawn_agent` | stdin | pinned argv | inherited | - |
   | grok | external runner | external runner | file | provider report | allowlist | Linux: Landlock and `bwrap` |
   | devin | external runner | external runner | file | provider report (export sidecar) | allowlist | macOS seatbelt or Linux bwrap with seccomp |

4. The parent launches each lane. `claude:opus@max` is native `Agent` with `pstack-opus-max`. `codex:gpt-6.1-sol@max` and `grok:grok-4.7@xhigh` are `pstack-runner` processes with the descriptor's provider, model and effort.

Every skill's dispatch contract already requires reading `provider-dispatch.md`, which links to the catalog, so a dispatch reads two files. One hand-written rule is new. A descriptor that matches no matrix row and no kept predecessor is an unregistered pair. It runs unchanged on an external route and on Codex's native route. A Claude-native route needs a generated agent, so an unregistered Claude model on a Claude Code parent is a dropout. The parent never guesses a replacement.

### How `/setup-pstack` finds a family's probe

Setup's probe table goes away. It repeated two facts the registry already holds: the route and the preflight. The new step 5 text stays the same across model and provider changes:

> Probe only the selected `provider:model@effort` pair of each assigned family. Find the family's provider in the [route table](../poteto-mode/references/model-catalog.md#routes). A native route gets a native one-turn probe: on Claude Code, the family's `pstack-<family>-<effort>` agent; on Codex, `spawn_agent` with the descriptor's model and `reasoning_effort`. An external route gets one `pstack-runner` call with a tiny read-only probe prompt. The runner's preflight checks the CLI, the login and the model, and its receipt is the result.

The Codex-parent access check before any probe reads the provider's host prerequisites and state paths from the catalog's provider notes. Steps 2, 3 and 6 match descriptors to matrix rows and kept predecessors. A first run seeds from the catalog's role defaults, and setup's in-file example sheet is deleted. A family whose only effort is `default` gets no effort question. Setup still treats an unregistered pair as inconsistent state; decision 2 changes only the runner. Setup's rerun, normalization, confirmation and byte-identical rewrite rules do not change.

```ts
const pre = lane.adapter.preflight;
let run = await runChild(lane, pre.argv(lane), { stdin: null, stdout: pre.stdout, deadlineAt, cancellation });
let verdict = pre.classify(run, lane);
if (verdict.kind === "unauthenticated" && pre.retryAfterUnauthenticatedMs !== null) {
  const wait = await waitWithinDeadline(pre.retryAfterUnauthenticatedMs, deadlineAt, cancellation);

}
```

```ts
// ── registry/contract.ts (new): the adapter contract ────────────────────────
declare const laneBrand: unique symbol;

/** A validated lane. resolveLane is the only constructor, so nothing downstream re-parses strings. */
export interface Lane {
  readonly [laneBrand]: true;
  readonly parent: Parent;
  readonly adapter: ProviderAdapter;
  /** A narrow view, so the contract does not import the adapter list. Null for an unregistered pair. */
  readonly family: { readonly name: string; readonly label: string; readonly model: string;
                     readonly rolling: RollingAlias | null } | null;
  readonly model: string;    // the descriptor's model component; the receipt's `model`
  readonly cliModel: string; // what argv passes; differs only for a registered family whose effort is part of the model ID
  readonly effort: Effort;
  readonly access: Access;
  readonly promptPath: string;
  readonly cwd: string;
  readonly outputPath: string;
  readonly receiptPath: string;
  readonly timeoutMs: number | null;
}

/** A rolling alias such as `opus`. Claude resolves it to the newest `claude-opus-<revision>`. */
export interface RollingAlias {
  /** Reports and versioned predecessors look like `<revisionPrefix><digits and hyphens>`. */
  readonly revisionPrefix: `${string}-`;
}

/** What one child process left behind. `sidecar` holds the provider sidecar's bytes, or null. */
export interface ChildRun {
  readonly exitCode: number | null;
  readonly stdout: string;
  readonly stderr: string;
  readonly sidecar: string | null;
}

export type PreflightVerdict =
  | { readonly kind: "passed"; readonly evidence: string }
  | { readonly kind: "unauthenticated"; readonly evidence: string } // only a preflight can say this (#142)
  | { readonly kind: "unavailable-model"; readonly evidence: string }
  | { readonly kind: "inconclusive"; readonly evidence: string };   // unreadable status (#71) → child-failed

export interface ProviderMetadata {
  readonly reportedModel: string | null;
  readonly sessionId: string | null;
  readonly usage: NormalizedUsage | null;
  readonly costUsd: number | null;
}

/** No "unauthenticated" kind: a model's output can quote the child's own work. */
export type ParseResult =
  | { readonly kind: "complete"; readonly text: string; readonly metadata: ProviderMetadata }
  | { readonly kind: "provider-failure"; readonly status: "cancelled" | "child-failed";
      readonly message: string; readonly metadata: ProviderMetadata }
  | { readonly kind: "malformed"; readonly message: string };

export type EnvPolicy =
  | { readonly kind: "allowlist"; readonly names: readonly string[]; readonly prefixes: readonly string[] }
  | { readonly kind: "inherit"; readonly dropPrefixes: readonly string[] };

/** Facts run.ts establishes before argv. Each is null unless the adapter asked for it. */
export interface LaunchFacts {
  readonly sharedGitDir: string | null;
  readonly providerSidecarPath: string | null;
}

export interface ProviderAdapter {
  /** The descriptor's provider component and the receipt's `provider`. */
  readonly id: string;
  /** Looked up on the child's PATH. Missing → unavailable-cli. */
  readonly executable: string;
  /** "flag": argv carries the effort, and omits the flag for `default`.
   *  "model-id": this provider's family entries map each effort to a CLI model ID. */
  readonly effortIn: "flag" | "model-id";
  readonly preflight: {
    argv(lane: Lane): readonly string[];
    /** "file": the child's stdout is a private reserved file that run.ts reads, then deletes. */
    readonly stdout: "pipe" | "file";
    /** One more preflight after an "unauthenticated" verdict, after this delay. null means none. */
    readonly retryAfterUnauthenticatedMs: number | null;
    classify(run: ChildRun, lane: Lane): PreflightVerdict;
  };
  readonly launch: {
    readonly prompt: "stdin" | "file";
    /** A provider sidecar the CLI writes. run.ts reserves a private directory and passes an absent path in it. */
    readonly providerSidecar: { readonly name: string } | null;
    /** resolveLane rejects any other access kind with a usage error, before launch. */
    readonly supports: readonly AccessKind[];
    needsSharedGitDir(access: Access): boolean;
    argv(lane: Lane, facts: LaunchFacts): readonly string[];
  };
  /** run.ts calls parse for every child that exits by itself. After a nonzero exit it honors only provider-failure. */
  parse(run: ChildRun, lane: Lane): ParseResult;
  readonly proof: {
    /** "absent": the CLI never reports the served model, so the exact argv is the evidence (pinned-argv). */
    readonly report: "required" | "absent";
    matches(lane: Lane, reported: string): boolean;
  };
  environment(access: Access): EnvPolicy;
  /** Markdown sentences that render.ts puts into provider-dispatch.md. */
  readonly docs: { readonly name: string; readonly hostPrerequisites: readonly string[];
                   readonly statePaths: readonly string[]; readonly notes: readonly string[] };
}

export function adapter<const A extends ProviderAdapter>(value: A): A {
  return value;
}
```

```ts
// ── registry/family.ts (new): family entries, role defaults, released pairs ──
import type { ADAPTERS } from "./providers.ts";

export type ProviderId = (typeof ADAPTERS)[number]["id"];
type EffortInOf<P extends ProviderId> = Extract<(typeof ADAPTERS)[number], { readonly id: P }>["effortIn"];

export interface KeptPredecessor {
  readonly model: string;
  /** The efforts setup accepts for this model today. Never inherited implicitly from the current model. */
  readonly efforts: readonly Effort[];
}

interface FamilyCommon<P extends ProviderId> {
  /** The key role defaults name. A Claude family's native agents are pstack-<name>-<effort>. */
  readonly name: string;
  /** The matrix label and the native agent's heading ("# pstack Opus lane"). */
  readonly label: string;
  readonly provider: P;
  /** The descriptor's model component. */
  readonly model: string;
  readonly defaultEffort: Effort;
  /** Cursor's selector for the same choice, kept for sync review. */
  readonly upstream: string | null;
  /** Present for Claude rolling aliases. Drives report matching and read-time normalization. */
  readonly rolling?: RollingAlias;
}

/** The provider picks the effort shape, so a Sol-shaped entry for a Devin model fails `tsc`. */
export type FamilyEntry<P extends ProviderId = ProviderId> = P extends ProviderId
  ? FamilyCommon<P> & (EffortInOf<P> extends "model-id"
      ? { readonly efforts: { readonly [E in Effort]?: string } } // effort → CLI model ID
      : { readonly efforts: readonly Effort[]; readonly predecessors?: readonly KeptPredecessor[] })
  : never;

export type LaneDefault<F extends string> = F | "inherit-parent" | "auto";

/** One model-sheet line: the role label users write, and its lanes in order. */
export interface RoleDefault<F extends string = string> {
  readonly role: string;
  readonly lanes: readonly LaneDefault<F>[];
}

/** A pair any model-matrix revision on main contained, and the family it must keep resolving to. */
export interface ReleasedPair<F extends string = string> {
  readonly pair: `${ProviderId}:${string}`;
  readonly family: F;
}

export function family<const F extends FamilyEntry>(entry: F): F {
  return entry;
}
```

### Where each invariant lives

**Types (`tsc --strict`):**

- A family's provider is registered, because `ProviderId` comes from `ADAPTERS`. Forgetting the list line makes `provider: "devin"` a type error.
- A family's effort shape matches its provider's `effortIn`.
- Role-default lanes name a family or an alias.
- Full access cannot be built on a read-only lane.
- `parse` cannot return `unauthenticated`.
- An adapter has no field for a timeout, a model-execution retry or another provider.
- Only `resolveLane` makes a `Lane`.

**Tests (`bun test`):**

- The model catalog and agent files match the render.
- Family names are unique and match `^[a-z0-9]+([.-][a-z0-9]+)*$`.
- `(provider, model)` is unique across families and kept predecessors.
- Efforts are non-empty, in `EFFORTS` order, and include `defaultEffort`. Only a listed effort is valid for a registered family, including `default`.
- Every released pair resolves to its recorded family, and every role-default pair is a released pair.
- The text scans and role-pointer checks below.
- Only `registry/providers.ts` imports `providers/*`.
- The adapter suite, once per adapter.

**Prose (hand-written in `provider-dispatch.md`):**

- The parent owns the route, and a child never reroutes.
- A dropout is not a fallback, and `--timeout` is the only deadline.
- Parent prerequisites, such as the Codex network-disabled sandbox.
- `ultra` appears only where the CLI lists it. That is a live fact, so each PR that changes an effort list cites the CLI output.

## The adapter contract in detail

### Preflight and auth classification

`preflight.argv` names one command, and `classify` returns a verdict. `run.ts` maps the verdict to a receipt status:

| Verdict | Receipt status |
|---|---|
| `passed` | the lane continues |
| `unauthenticated` | `unauthenticated`/77 |
| `unavailable-model` | `unavailable-model`/69 |
| `inconclusive` | `child-failed`/70, message "authentication preflight output was inconclusive" |

| Provider | Command | Passes when |
|---|---|---|
| claude | `claude auth status --json` | exit 0 and JSON `loggedIn === true` |
| codex | `codex login status` | `/logged in/i` |
| grok | `grok models` | a login line (`logged in`, `You are using XAI_API_KEY.`, `You are authenticated via deployment key.`) and the model listed under `Available models:` |
| devin | `devin auth status` | exit 0 and `^Logged in` |

- **Unknown output.** Claude, Codex and Grok keep today's fallback to `unauthenticated`. New adapters use `classifyFailure(run, "inconclusive")`, so unreadable output is never read as a logged-out CLI. Cursor's empty piped status (#71) needs exactly that.
- **API-key logins (#58).** Login kinds are adapter knowledge. Grok's API-key and deployment-key lines are measured. Whether Claude reports `loggedIn: true` for API-key auth, and what Codex prints for an API-key login, are unverified.
- **Evidence.** A passed preflight records a fixed summary, such as "authenticated; model grok-4.7 available". A failed one records bounded raw output. An adapter whose status output can carry tokens returns redacted evidence; Cursor prints access and refresh tokens (#94).
- **Retry.** Only `retryAfterUnauthenticatedMs` requests another attempt. Grok sets 5000. `run.ts` waits under the lane's one deadline and cancellation latch, runs the same preflight once more, and records both attempts.

### Argv for each access mode

`launch.argv(lane, facts)` builds the full argv. Today's mappings move into each adapter unchanged:

| Provider | read-only | isolated-write |
|---|---|---|
| claude | `--permission-mode plan` and `--tools Read,Grep,Glob,Bash` | `acceptEdits` and the `--settings` Bash sandbox (`failIfUnavailable`, `allowUnsandboxedCommands: false`, `denyWrite: [sharedGitDir]`) |
| codex | `--sandbox read-only` | `--sandbox workspace-write` |
| grok | `--permission-mode auto --sandbox read-only` and read tools | `auto --sandbox workspace` and `search_replace` |
| devin (unverified) | `--permission-mode auto --sandbox` | `--permission-mode accept-edits --sandbox` |

- **`default` effort.** A flag adapter omits its effort flag (`--effort`, `model_reasoning_effort`, `--reasoning-effort`). A Codex-native lane omits `reasoning_effort`. A model-ID adapter reads the CLI model ID from the family entry.
- **Shared `.git` deny.** `needsSharedGitDir` replaces the `provider === "claude" && mode === "isolated-write"` branch. `run.ts` still runs `discoverSharedGitDir` under the lane deadline and turns a refusal into a receipt. An adapter cannot spawn git itself.
- **Unsupported modes.** `launch.supports` lists the access kinds an adapter can run. `resolveLane` refuses any other kind before launch. If U5 shows that Devin has no bounded writer mode, the Devin adapter lists only `read-only`.
- **Devin.** The flags are measured, but their combined behavior is not. U5 must capture what print mode does when a tool needs approval, whether `accept-edits` lets a writer run shell commands, and whether flags exist to turn off recursion and web access. `smart` (a fast model approves) and `dangerous` (approves every tool) are not bounded modes.
- **#80 full access.** Codex adds `"isolated-write-full-access"` to `supports` and maps it to `--sandbox danger-full-access`. The runner gains `--writer-sandbox <bounded|full-access>` with default `bounded`. The receipt records `writerSandbox`. No code path sets the opt-in, and nothing retries with it after a sandbox failure. The adapter suite checks that bounded argv never contains a token from one shared deny list (`danger-full-access`, `bypassPermissions`, `--dangerously-skip-permissions`, `--always-approve`, `dangerous`). That extends today's "uses bounded write modes without blanket bypasses" test to every adapter. A native Codex writer on a Codex parent keeps the parent's sandbox.

### Prompt delivery

`launch.prompt` takes two values. With `"stdin"`, `run.ts` writes the prompt to the child's stdin and closes it (Claude, Codex). With `"file"`, stdin is ignored and argv must contain `lane.promptPath` (Grok, Devin). The adapter suite checks both directions. A stdin defect such as #94's `EPERM` stays in `run.ts`, where one fix covers every provider.

### Output parsing, provider sidecars, failures and cancellations

**Provider sidecar.** When an adapter declares one, `run.ts` creates `<receipt>.provider/` exclusively with mode 0700 and passes the absent path `<receipt>.provider/<name>` in `facts`. It reads the file after exit and records the path in the receipt's `providerSidecarPath`. The directory gets the same distinctness and rollback rules as the other reserved paths. The measured Devin probe created its export at an absent path. Whether Devin accepts a pre-created file is unknown, so the design does not pre-create it.

**Parsing.** `parse` sees every child that exits by itself, and `run.ts` applies one rule to every provider:

- After exit 0: `complete` goes to model proof. `provider-failure` gives its status. `malformed` gives `malformed-output`/65. A missing required sidecar is `malformed`.
- After a nonzero exit: only `provider-failure` is honored. That is Grok's terminal result event: `cancelled`/130 or `child-failed`/70, keeping the message and metadata (#78). Anything else takes the ordinary classification: `child-failed`/70, or `unavailable-model`/69 when the model-error text matches.

Grok's cancellation detection (`stop_reason`, `subtype`, `PermissionCancelled`) stays inside `grok.ts`. Launcher cancellation and an explicit timeout never reach `parse`.

**Devin, measured.** The 2026-10-11 probe exited 0, printed only the final text on stdout, and wrote ATIF-v1.7 JSON to the export path. The parser reads `session_id`, `steps[-1].extra.generation_model` (falling back to `steps[-1].model_name`) and `final_metrics` token totals. It ignores `agent.model_name`, which is a label ("SWE-2 Medium"). Cost stays null. Failure, cancellation and logged-out shapes are not captured yet.

### Model proof

`run.ts` owns the decision. Adapters supply only `proof.report` and `proof.matches`:

```ts
function modelProof(lane: Lane, reported: string | null): ModelProof {
  // reported and matches(lane, reported) → modelVerified true, modelEvidence "provider-report"
  // reported null and proof.report "absent" → modelVerified false, modelEvidence "pinned-argv"
  // otherwise → modelVerified false, modelEvidence null → dropout
  throw new Error("not implemented");
}
```

| Family kind | A report matches when |
|---|---|
| Rolling alias (`opus`) | it is `<revisionPrefix><digits and hyphens>` for that family |
| Exact Claude pin (`claude-opus-5-5`, #54) | it is identical, or the same ID followed by `-<date>` (unverified what Claude reports) |
| Codex (`report: "absent"`) | no report is expected; the suite checks that no Codex fixture reports a model |
| Effort in the model ID (Devin) | it equals `lane.cliModel` (`swe-2-high`); the family slug `swe-2` is not enough |
| Grok | exact, or the requested ID followed by `-` (today's rule) |

A report that does not match is a mismatch. It never falls back to `pinned-argv`. An unregistered pair has no family, so Claude and Grok use exact-or-prefix matching, Devin compares with `lane.cliModel`, and Codex stays `pinned-argv`. That is today's behavior for a model the matrix does not list.

### Environment isolation

`environment(access)` returns data, and `run.ts` applies it to the preflight and the model call:

- **Inherit:** Claude and Codex. A Claude writer drops `GIT_*`.
- **Allowlist:** Grok and Devin. `BASE_ALLOWLIST` is today's Grok list: `PATH HOME USER LOGNAME SHELL TMPDIR LANG TERM COLORTERM TZ`, the proxy variables in both cases, and `SSL_CERT_FILE SSL_CERT_DIR NODE_EXTRA_CA_CERTS`. The base prefixes are `LC_` and `XDG_`. Grok adds `GROK_` and `XAI_`. Devin adds nothing, so an inherited `DEVIN_PERMISSION_MODE`, `DEVIN_SANDBOX` or `DEVIN_MODEL` cannot widen a lane or change its model.

New adapters start from the allowlist, because their shells can read every variable they inherit (#141). After the adapter's policy, `run.ts` always drops the parent's identity markers. The `pstack-runner` launcher still keeps project `.env` files and Bun config out (#25).

### Host prerequisites

`docs.hostPrerequisites` and `docs.statePaths` render into the route table and the provider notes. Setup's Codex-parent access check reads them. The runner does not test them. A sandbox refusal stays `child-failed`, with the CLI's text in `error.evidence` (#56). Parent prerequisites, such as Codex's network-disabled sandbox and its post-failure hint, stay hand-written prose and `run.ts` policy, because they belong to the parent rather than the provider.

### Preflight stdout to a file (#71)

`preflight.stdout: "file"` makes `run.ts` reserve `<receipt>.preflight` exclusively with mode 0600 and pass its descriptor as the child's stdout. `run.ts` reads the file after exit and deletes it in a `finally` block, so status bytes that can hold tokens do not persist. Cursor's measured status prints JSON to a regular file and nothing to a pipe. If `run.ts` is killed between the read and the delete, a 0600 file can remain next to the receipt.

### Policies that stay in `run.ts`

No adapter field can change these:

- Same-provider rejection.
- Only `--timeout` creates a deadline. It is one absolute deadline across setup, preflight, the retry wait, model execution and the drain.
- Exactly one model execution. No retry of model execution, no fallback model, no other provider.
- At most one preflight retry, and only after `unauthenticated`.
- The cancellation latch and `terminate` semantics.
- Exclusive private reservation of the output, receipt, `.stdout`, `.stderr`, provider sidecar directory and preflight capture.
- Receipt shape (`schemaVersion: 1`) and exit codes.
- Status precedence: launcher cancellation, then timeout, then provider failure, then nonzero exit, then malformed output, then model proof.
- `unauthenticated` only from a preflight.
- Parent identity scrubbing, the Codex-parent network hint, and the 4,000-character evidence bound.
- `complete` requires `provider-report`, or `pinned-argv` from an adapter that declares `report: "absent"`.

## Migration

### Existing model sheets

The descriptor grammar, the role labels and the `inherit-parent` and `auto` aliases do not change.

- **Rolling Claude aliases.** `claude:fable` and `claude:opus` resolve as `current`. The ten agent files regenerate with identical bytes.
- **Read-time normalization** keeps today's rule, now generated from `rolling.revisionPrefix`. An unregistered `claude-fable-<revision>` or `claude-opus-<revision>` normalizes in memory. The runner rejects one that was not normalized, with today's message.
- **`codex:gpt-5.6-sol`** becomes a kept predecessor of the Sol family. The runner dispatches it unchanged. Setup proposes `gpt-6.1-sol` at the same effort and keeps the old model if the operator declines. Its efforts stay `low` to `ultra`, as setup accepts today; Codex CLI 0.159.0 lists `ultra` for `gpt-5.6-sol`. The entry states them explicitly instead of inheriting them from the Sol row.
- **`grok:grok-4.6`** becomes a kept predecessor too. Releases before v1.5.0 wrote it. Today the runner still runs it, but setup treats it as inconsistent state: setup stops and requires an explicit replacement, and it cannot keep the old model. With this change setup proposes `grok-4.7` at the same effort and keeps `grok-4.6` if the operator declines, the same rule as `gpt-5.6-sol`.
- **Released pairs.** `RELEASED_PAIRS` turns "existing sheets keep working" into a checked rule. Every pair any model-matrix revision contained must resolve to its family, and every current role-default pair must be in the list. A model bump that forgets a kept predecessor then fails `bun test`. That test would have caught the `grok-4.6` gap.
- **Unregistered pairs.** The runner keeps passing an unregistered `(provider, model)` pair to the CLI, as it does today (decision 2). A new model can run from a hand-edited sheet before its family entry lands. On a model-ID provider such as Devin, the descriptor names the CLI model ID with the `default` effort, for example `devin:swe-1-7-medium@default`. A model the CLI does not serve ends as the CLI's own failure: a dropout, never a substitution.

```ts
  efforts: UP_TO_MAX, defaultEffort: "max", upstream: "claude-opus-5-5-xhigh" }),
```

- `resolveModel` checks exact entries before rolling patterns. `claude:claude-opus-5-5@max` resolves to the pin, and every other `claude-opus-<revision>` still normalizes to `opus`.
- `RELEASED_PAIRS` blocks the case that would change old sheets. A pin entry for `claude-opus-5` fails the test, because an earlier matrix contained `claude:claude-opus-5` and it must keep resolving to `opus`.
- No model-matrix revision ever contained `claude-opus-5-5`. The orchestrator checked every revision of the matrix in `provider-dispatch.md`; the only pairs were the eight in `RELEASED_PAIRS`. A sheet line `claude:claude-opus-5-5` can only come from a hand edit, and it names the same model the rolling alias serves today.
- The pin gets native agents `pstack-opus-5-5-<effort>` with `model: claude-opus-5-5`. Whether Claude Code accepts a full model ID in agent frontmatter is unverified.
- Sonnet is one more rolling family: `{ name: "sonnet", model: "sonnet", rolling: { revisionPrefix: "claude-sonnet-" }, … }`, plus five generated agent files.

## Shapes compared

- **A (chosen): typed TypeScript registry, providers as code modules, generated markdown.** Described above.
- **B: one JSON file that the runner and the parent both read; providers as declarative data.** `poteto-mode/references/registry.json` holds families, role defaults and provider definitions. Provider definitions are argv templates with mode maps, regex and JSON-path preflight predicates, and named parser kinds (`json-object`, `jsonl-terminal-event`, `atif-sidecar`). One generic engine in `run.ts` interprets them. `provider-dispatch.md` says "read registry.json". Agent files are still generated, because they must be static.
- **C: markdown stays the source.** People edit the tables in `provider-dispatch.md` by hand. The runner parses those tables at startup. Providers are code modules, and agent files are generated from the parsed tables.

| Criterion | A | B | C |
|---|---|---|---|
| Interface depth | Public surface: `resolveLane`, `resolveModel`, `REGISTRY`, `defaultDescriptor`. Only `run.ts` sees the adapter contract. Hidden: normalization, predecessors, pin precedence, effort binding, argv, parsing, env | The schema is the interface. Every parser kind and predicate form is something an entry author must learn, so learning the interface means learning the engine | The table format, including a cell syntax for an effort-to-ID map, becomes an API shared by people, the parent and a runtime parser |
| Adding Devin | two new files, one list line, one entry; `run.ts` unchanged | a JSON block plus engine work for a new parser kind (the ATIF sidecar), because each real CLI so far needed something new | adapter, list line, table rows, and a parser change for the new cell syntax |
| Risk to other providers from a new provider | none in code: `run.ts` and the other adapters do not change | every provider, because the shared interpreter changed | every provider, because the shared markdown parser changed |
| Default-model change | one file | one file | one table row, which is also runner input |
| Cursor sync cost | role pointers only | same | same |
| An agent that opens one file | copying Sol into Devin fails `tsc`; forgetting `providers.ts` fails `tsc`; a hand edit of a table fails the drift test with the write command; importing an adapter from `run.ts` fails the import-boundary test | copying a provider block that lacks a needed feature gives wrong behavior at run time, or needs an engine edit outside the "one entry" | a typo in a cell is found only when the runner parses it at dispatch time |
| What the parent reads | the hand-written rules and one generated catalog with precomputed descriptors | JSON plus dispatch rules; the parent composes descriptors from family references | one hand-maintained file |

**Why A.** B removes generated copies, but its engine turns each new CLI into a change to shared code that every provider runs. C keeps the friendliest source for people, but it makes a documentation table into runtime input, and Devin's effort-to-model-ID map has no natural cell. A is the only shape where a provider change touches no shared code and a model change touches no Cursor-derived file.

## Synthesis decision

This design came from `pstack:architect`. The orchestrator is the Claude Code session that ran the skill on Opus 5.5. It wrote the Phase A grounding from direct reads of the runner, the dispatch reference, setup, the tests and the waiting issues, plus the CLI measurements listed under "Evidence". Phase B ran an arena with the `architect runners` default panel. Each runner received the same prompt and grounding and worked read-only:

| Runner | Route | Result |
|---|---|---|
| `claude:opus@max` | native `pstack-opus-max` | returned its package (native transcript, no receipt) |
| `codex:gpt-6.1-sol@max` | external runner | `complete`, `pinned-argv`, 1,397,736 ms |
| `grok:grok-4.7@xhigh` | external runner | `complete`, `provider-report` `grok-4.7-build`, 996,601 ms |

All three chose the same whole shape: providers as typed code, family entries as data, generated markdown and agent files, and role pointers in Cursor-derived files. That is strong agreement on the shape. They differed on layout and on the edge decisions.

The cross-judge was a separate `codex:gpt-6.1-sol@max` lane, read-only, with the candidates relabeled A (Opus), B (Sol) and C (Grok). Its receipt is `complete` with `pinned-argv` evidence (916,355 ms). It scored B 25, A 23 and C 18 out of 30 and recommended B as the base. It also checked candidate claims against the source and found four that change this design:

- The Opus candidate narrowed the kept `gpt-5.6-sol` to `low` through `max`. Setup accepts `ultra` for it today, and Codex lists `ultra` for it. This design keeps `ultra`.
- The Opus candidate said the existing run tests pass unchanged. `runLane` takes a `Lane` here, so the tests change how they build a lane. Their assertions stay.
- Every candidate claimed a new provider needs only its own live checks. In fact, any change under `poteto-mode/references/**` makes the verifier select every skill plus the setup, runner and shipped-tools checks (`.claude/skills/verify-open-pstack/scripts/core.ts:31`). With generated content inside `provider-dispatch.md`, every registry change would keep today's full live gate. Decision 6 answered this with a separate generated file and a narrower verifier feature.
- The verifier's setup case matches descriptors with its own `(?:claude|codex|grok):` pattern (`features/recipes.ts:269`), besides `ROUTE`. U5 generalizes both.

**The orchestrator kept the Opus candidate as the base, against the judge's recommendation.** The judge preferred B because it puts each provider's adapter, family entries and fixtures in one entry of one `registry.ts`. Three reasons decided against that:

- The roadmap (`docs/plans/2026-10-01-triage-and-roadmap.md`, section 3, item 2) gives each provider its own `runner/providers/<name>.ts` and says that Devin then needs "one adapter, one fixture, and one registry row". The Opus candidate matches that. B puts every provider's code in one file, so an agent editing one provider opens all of them.
- B adds surface that this issue does not need: a planning stage and an artifact-record stage between the runner and the adapter, receipt schema version 2, a separate registry key next to the family name, and `@none`. The judge also scored B's simplicity 3 of 5.
- The judge's two strongest objections to the Opus candidate were the narrowed Sol efforts and the run-test claim. Both are corrected above. The judge's third objection was about exact pins. Decision 4 kept the registered entry, against the judge's preference for the `=` spelling.

**What the Opus candidate contributed.** It had the deepest contract, typed guards against the mistakes an agent copying one file would make, and two grounding findings that I verified: the stale "GPT-5.6 Sol max" in `poteto-mode/SKILL.md:94`, and the `grok-4.6` released pair that no rule covers. Its `RELEASED_PAIRS` rule turns "existing sheets keep working" into a test.

**Grafts:**

- From the Sol candidate: the provider sidecar path is absent inside a private directory the runner reserves, instead of a pre-created file, because Devin's handling of an existing file is unmeasured. An adapter declares the access modes it supports (`launch.supports`), so an unmeasured or unsafe mode is refused before launch; the judge named this refusal as B's safest choice. Decision 4 rejected its `=` exact-pin spelling. Decision 5 replaced its `@none` effort with `default`, because `none` already means "no reasoning" for GPT models on Devin.
- From the Grok candidate: the #80 opt-in is a field on the writer access (`Access.sandbox`), not a third access mode, so the two access modes keep their meaning. The judge recommended this graft. Units U1 and U2 keep behavior, and U3 is the one user-visible cutover. Every adapter runs one property suite: the default effort is selectable, argv contains the requested model or its effort-specific ID, and bounded argv contains no bypass token.

**Rejected:**

- The Sol candidate's single `registry.ts` file. Every provider's code then shares one file, and an agent editing one provider reads all of them.
- The Grok candidate's directory scan of `providers/`. `tsc` does not check a runtime scan, and a static list plus a derived `ProviderId` makes a missing registration a type error.
- The Sol candidate's separate `setup-models.md`, which moves setup's whole procedure out of the Cursor-derived file. It is a bigger divergence than this issue needs, because only the probe table and the example sheet change with models.
- Receipt schema version 2. Additive nullable fields keep version 1, as `stdoutPath` did.
- `placement` and `catalogOrder` fields. Optional status derives from role defaults, and matrix order is array order.

## Tradeoffs accepted

- We accept a generated file committed beside hand-written ones, and a second file read per dispatch. In exchange we get one typed source, precomputed tables for the parent, and a narrower live gate for model changes.
- We accept that an unregistered pair skips the per-family effort check in the runner. In exchange a new model runs from a hand-edited sheet before its family entry lands.
- We accept one more divergence on twelve Cursor-derived lines and a smaller setup. In exchange, no model or provider change touches those files again.
- We accept markdown sentences inside adapter modules (`docs`). In exchange, provider notes sit next to the argv they explain.
- We accept merge conflicts in the model catalog when two registry PRs overlap. Regenerating resolves them, and the drift test catches a stale catalog on the queued head.
- We accept a ten-member adapter contract. Its only consumer is `run.ts`, and each member hides behavior specific to one CLI.

## Alternatives considered

- **JSON family entries with code adapters** (B with providers as code). Role defaults then need either composition by the parent model or a second, hand-synced descriptor list.
- **A resolver command that the parent asks for role defaults.** Setup forbids a runtime resolver, and the parent would depend on a subprocess to read its own defaults.
- **Generated regions inside `provider-dispatch.md`.** The parent would read one file, but every model or provider change would select the verifier's `shared` feature and run every skill check. Decision 6 chose the separate catalog instead.
- **The runner rejecting unregistered pairs.** It would check every effort against a family, but a new model could not run until its entry merged. Decision 2 kept today's pass-through.

## Decisions

Eric answered the six open questions on 2026-10-11:

1. **Approve the design: yes.** Implementation issues: U1 #155, U2 #156, U3 #157. U4 to U7 stay in their existing issues (#54, #69, #80).
2. **Runner rejects unregistered pairs: no.** The runner passes an unregistered pair to the CLI unchanged, as today. On a model-ID provider the descriptor names the CLI model ID with the `default` effort.
3. **`grok-4.6` as a kept predecessor: yes.** Setup proposes `grok-4.7` at the same effort and keeps `grok-4.6` on a decline.
4. **A registered exact pin wins over the rolling pattern: yes.** `claude:claude-opus-5-5@max` pins once #54 adds that family entry. The descriptor grammar does not change.
5. **The single effort of a model without effort tiers is named `default`.** `devin:swe-1.6@default` runs `--model swe-1-6`. On a flag provider, `default` omits the effort flag.
6. **Generated content goes in a separate file.** The model catalog is `references/model-catalog.md`, with its own verifier feature, so a model change no longer runs every skill check.

Two decisions belong to their own issues: the model-sheet syntax for the #80 opt-in, and whether Devin's research-preview `--sandbox` counts as bounded for #69.
